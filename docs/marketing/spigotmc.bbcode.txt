[CENTER][SIZE=7][B]LightLogin[/B][/SIZE]
[SIZE=5][COLOR=#5b8cff]A login and registration plugin that treats your players' passwords like they actually matter.[/COLOR][/SIZE]

LightLogin handles registration and login for Spigot and Paper servers on Minecraft 26.2 and newer. It is a complete rewrite of the original LightLogin, rebuilt from the ground up rather than patched.

This is the full feature list, because you came here to find out what it does.

[HR][/HR]

[SIZE=6][B]Everything it does[/B][/SIZE]

[SIZE=5][B]Accounts and passwords[/B][/SIZE]
[LIST]
[*]Register and login commands, with every message in the plugin fully configurable
[*]Password change, email based password reset, and staff issued temporary passwords
[*]Account removal, either self service or performed by staff
[*]A password policy you control: minimum length, required character classes, a common password blocklist, banned substrings, and a rule against using the username
[*]Account lockout after repeated failed attempts
[*]Session resumption, so a player who reconnects shortly after logging in is not asked again
[*]A complete audit trail of every login, registration, reset, ban and administrative action
[/LIST]

[SIZE=5][B]Anti bot and abuse protection[/B][/SIZE]
[LIST]
[*]Two CAPTCHA modes: a simple arithmetic question, or a proof of work challenge that makes automated floods genuinely expensive
[*]Per IP login rate limiting
[*]Per IP registration limits, so one address cannot create accounts in bulk
[*]Join flood throttling, which rejects a connection burst before a player is ever created
[*]IP and CIDR bans, permanent or timed, with a reason attached and a record of who applied it
[*]Country blocking through a MaxMind GeoLite2 database, for servers that want to close a region
[/LIST]

[SIZE=5][B]Privacy and anonymity[/B][/SIZE]
[LIST]
[*]Passwords are typed into a private in game window, so they never become a chat message, a command argument or a shell history entry
[*]Credential commands such as login, register and changepassword are stripped from your console and your log files
[*]Chat messages that look like a password are blocked, so nobody leaks one by accident
[*]A configurable blindness effect while a player is logged out
[/LIST]

[SIZE=5][B]The login world[/B][/SIZE]
[LIST]
[*]Logged out players can be parked in a completely blank world instead of your real map
[*]Generated in the End or in the overworld, your choice from the config
[*]No terrain, no structures, no mob spawning, nothing ticking. It is a place to stand and nothing else
[/LIST]

[SIZE=5][B]Administration[/B][/SIZE]
[LIST]
[*]A full administration website hosted by the plugin itself on a local address. No extra service, no separate process, nothing else to install
[*]Dashboard with live account, ban, session and audit counts
[*]A searchable player list and a per player page with all of their history
[*]Reset passwords, ban or unban addresses, remove accounts, all from the browser
[*]Loopback only by default, with token based sessions, CSRF protection on every action and optional two factor authentication through any authenticator app
[*]An in game moderation menu for staff, to browse players, reset passwords, ban addresses and read stats
[/LIST]

[SIZE=5][B]Storage[/B][/SIZE]
[LIST]
[*]SQLite out of the box, with nothing to install
[*]MySQL, MariaDB and PostgreSQL supported when you would rather use one
[/LIST]

[SIZE=5][B]For developers[/B][/SIZE]
[LIST]
[*]Events fired on login, registration and failed attempts
[*]A read only API so your other plugins can check who is authenticated
[/LIST]

[HR][/HR]

[SIZE=5][B]Why your players' passwords are safe here[/B][/SIZE]

Passwords are stored with Argon2id, the current standard for password hashing and the same family of algorithm used by modern password managers. Each account gets its own random salt, and you can set a secret server side pepper as well, so a stolen database copy is useless to whoever took it. Every account is quietly upgraded to stronger settings the next time its owner logs in.

[HR][/HR]

[SIZE=5][B]Why it will not lag your server[/B][/SIZE]

Hashing a password properly is deliberately expensive, so LightLogin does all of it away from your server's main thread. A hundred players logging in at once becomes a short queue instead of a freeze, and only a bounded amount of that work is ever allowed to run at once, so a login flood cannot eat your memory either.

[HR][/HR]

[SIZE=5][B]Why the jar is only 1.7 MB[/B][/SIZE]

It carries only what it always needs. Database drivers and the optional GeoIP reader are fetched at startup if your server does not already have them, and every file is verified by checksum before it is used. Prefer no downloads at all? Switch them off in the config and place the files yourself.

[HR][/HR]

[SIZE=5][B]Requirements[/B][/SIZE]
[LIST]
[*]Spigot or Paper 26.2 or newer
[*]Java 25 or newer
[*]Optional: MySQL, MariaDB or PostgreSQL. SQLite is included and is the default
[*]Optional: an SMTP account if you want email based password recovery
[*]Optional: a MaxMind GeoLite2 country database for nation blocking
[/LIST]

[HR][/HR]

[SIZE=5][B]Install[/B][/SIZE]
[LIST=1]
[*]Drop [FONT=Courier New]lightlogin-paper-3.0.0.jar[/FONT] into your [FONT=Courier New]plugins/[/FONT] folder.
[*]Start the server once. LightLogin writes its config, its messages and a master key into [FONT=Courier New]plugins/LightLogin/[/FONT].
[*]Set the pepper environment variable. Strongly recommended, and worth doing on day one.
[*]Review the config and restart.
[*]To use the administration website, enable it in the config and restart. The first time, it prints an administrator username and password to your console. Change that password once you have signed in.
[/LIST]

[HR][/HR]

[SIZE=5][B]Testing[/B][/SIZE]

149 automated tests, and they do not all live in a happy path. The suite includes the real admin website driven over a socket, the real database layer against a real SQLite file, an audit that every config key is actually read and every message key actually exists, and six tests that load the packaged jar itself and check that password hashing still works using only what shipped inside it.

Those packaging mistakes are invisible to an ordinary unit test, which is exactly why they are checked here instead of on your server.

[HR][/HR]

[SIZE=5][B]Documentation[/B][/SIZE]

Nine documents ship in the repo: the security design and the reasoning behind the algorithm choices, the architecture, the security model, every configuration key, the command and permission reference, the admin panel, migration from the original plugin, development and testing, and the plugin API.
